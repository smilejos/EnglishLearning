# 情境教材：產生與匯入流程

更新日期：2026-10-09。使用者已選擇每張十五個目標詞，第一輪先做「午後客廳」一個完整試點。

目前完成的是參考圖、十五詞故事套件與唯讀預檢工具。情境資料表、匯入器、故事音檔與學習頁尚未實作，也尚未寫入正式資料庫。

## 第一輪交付範圍

先讓一個情境完成「看圖 → 聽英文故事 → 點選單字卡 → 隱藏標籤回想」，確認畫面密度、故事長度與點選方式，再擴展其餘情境。聽音找圖、練習紀錄與整批自動生成留待試點後安排。

| 項目 | 客廳試點現況 |
| --- | --- |
| 十五個目標詞 | 已比對來源字庫 GUID、分組、詞性與本次詞義：basic 12、advance 3 |
| 效果參考圖 | 已產生，保留原八詞版；英文標籤仍畫在圖片內 |
| 英文故事與繁中翻譯 | 已整理草稿：8 句、75 個英文單字，涵蓋全部十五詞 |
| 故事點字資料 | 保存所有字形位置與字庫 GUID，屈折字形明確連回原詞 |
| 唯讀套件預檢 | 已實作；可檢查來源關聯、故事覆蓋、座標格式、檔案 hash 與缺件 |
| 正式底圖、互動位置、英文旁白 | 待準備 |
| 資料庫匯入、API、學習頁 | 待實作及驗收 |

[客廳套件與故事](packages/living-room-15-v1/README.md) 是第一輪的內容起點；[scenario.json](packages/living-room-15-v1/scenario.json) 是離線套件格式，尚無 API 接受它。

## 1. 先確認故事與選詞

使用 `level.list` 的 basic／advance 聯集選詞；本試點的十五詞與支援詞均已比對來源檔。每個目標詞保存 `entryGuid`、`word`、`list`、`teachingPos` 與 `senseZh`，讓圖、故事和單字卡共用同一詞條。

故事採英文朗讀，繁中翻譯以文字展開，不另做中文朗讀。`reads → read`、`sleeps → sleep`、`books → book` 等關聯保存於逐句 `wordLinks`；單字卡播放的是原形單字錄音。預檢會核對字形範圍及 GUID，但不判斷字形與原詞是否為正確文法關係，仍須人工審閱故事、翻譯、詞義及畫面是否一致。

故事定稿後再產音，避免文字改動造成重做。旁白先使用目前既有的語音設定，實際產生前確認該次聲線與文字；不要在測試時呼叫真實生成服務。

## 2. 準備無文字底圖與互動標籤

已確認的十五詞圖可以作為風格與構圖參考，但圖上的文字無法由網頁開關隱藏。正式版另做同構圖的無文字底圖，將英文標籤、箭頭與點選入口疊在網頁上。

套件的 `generationPlan.baseImage` 已保存十區塊編輯提示詞，尚未執行。產生後人工核對十五個物件、動作與舒適感線索；確認清除標籤、書本裝飾文字及時鐘數字時沒有破壞圖像辨識。

每詞記錄標籤位置 `interaction.label` 與指向位置 `interaction.object`，x／y 均使用 0–1 的圖片比例座標，供不同螢幕尺寸定位。動詞指向動作，形容詞指向孩子的放鬆姿勢；read／book、sleep／pillow 共用畫面區域時，以標籤和圖下單字按鈕區分。第一版採可點選標籤及標記，不要求先描出每件物品的完整輪廓。

手機保留放大圖片與圖下十五詞清單。回想模式隱藏英文標籤、故事及翻譯，揭曉後開放單字卡。

## 3. 準備旁白與核對已有字庫音檔

新增一段完整英文故事音檔，與既有單字、英文解釋、英文例句錄音分開，不拼接既有錄音當成旁白。`assets.storyAudio.textSha256` 保存本次英文故事的 hash，故事修改後預檢會拒絕舊旁白 metadata。

basic 原有音檔優先沿用，仍要核對實際檔案與 metadata。advance 的 curtain、shelf、pillow 逐詞查缺，若缺錄音，先列出本試點需要的單字、解釋及例句補音範圍，再執行生成，不為一個客廳試點重做整個 advance 字庫。

故事、單字與例句接入既有音源仲裁：開卡不自動播放；播放單字或例句時暫停故事並保留位置，使用者可自行繼續聽故事。

## 4. 執行離線預檢

從專案根目錄執行：

```bash
npm run scenario:package:check -- docs/scenarios/packages/living-room-15-v1/scenario.json
npm run scenario:package:test
```

此工具不載入環境檔、不連資料庫、不產生圖片或音檔，也不匯入資料。現有草稿預期為 `valid: true`、`publishReady: false`，缺十五組互動座標、正式底圖與英文故事音檔。

素材與座標補齊後，使用嚴格檢查：

```bash
npm run scenario:package:check -- docs/scenarios/packages/living-room-15-v1/scenario.json --require-publish-ready
```

缺件或不一致時回傳非零結束碼。`publishReady` 只表示套件欄位與檔案預檢通過，不代表圖片內容、音檔品質、正式字庫音檔或上線流程已驗收。圖片是否無文字仍依人工審閱標記，工具沒有 OCR；音檔是否真的朗讀該故事也須實際聆聽。座標、詞形與翻譯的語意品質不能單靠結構檢查判定。

## 5. 再接資料庫、API 與學習頁

新增獨立的情境、版本、目標詞及媒體關聯，提供可重跑且相同版本不重複建立的匯入流程。先在 `_test` 資料庫用假生成 client 驗證，再作本機預覽；不用文章 seed 或 POST /articles 代替情境匯入。

既有文章圖片流程綁定文章與段落，規劃也有少量 teaching tokens 的限制，因此情境需有自己的內容與發布關聯。可重用圖片供應商、儲存與音訊工具，另補情境圖片的權限判定，維持 reader 只看已發布版本。

單字 API 補上按 GUID 取得指定字庫詞條；學習頁沿用字庫的定義、解釋、例句與有效音檔，抽出共用單字卡，不虛構文章來源。點字或播放不自動收藏。故事與圖片上的詞形都使用套件指定 GUID。

正式匯入前，準備可檢視的 migration、目標資料庫識別、素材落點、匯入內容與試點驗收結果，再依 [AGENTS.md](../../AGENTS.md) 的正式庫寫入規則取得確認。部署、素材 metadata 寫入與發布都須說清楚具體範圍；不因套件預檢通過就自動啟動 worker 或正式服務。

## 後續的產生 UI

完整試點跑通後再增加後台：貼上單字 textarea → 字庫匹配與十五詞確認 → 選擇風格／場景／標籤預設 → 審閱故事和圖 → 產音 → 發布。常用設定使用預設範本，十區塊提示詞收在進階設定，不要求每次填十個欄位。

第一輪先採離線套件加素材匯入，可及早發現內容與資料模型缺口；確認同一套內容能順利呈現與練習後，再擴展四十個情境與批次生成。
