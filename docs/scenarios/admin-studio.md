## 製作流程

後台的「情境製作」提供草稿清單。建立草稿後依序操作：

1. 貼上單字或搜尋字庫，依底圖選定 1–25 個目標詞。選詞方向為 15 名詞、5 形容詞及最多 5 動詞，線索不足可以少選，不硬湊配額。確認詞性及本次中文詞義；保留字庫 GUID，重複詞、找不到的詞及分級不符會提示。
2. 填寫標題、情境識別字與場景描述，選擇圖片風格及模型。常用設定有預設，十區塊 Prompt 位於進階設定。目標詞由選詞自動整理；標籤由網站疊加，圖片本身固定不生成文字。
3. 手動產生英文故事與繁中翻譯，逐句編輯並核對詞形對應。無法連到既有字庫或有歧義的詞須修正，才可完成教材。生成提示依實際目標數量要求全詞覆蓋，不固定十五詞。英文故事朗讀，繁中翻譯只提供文字；可用 optional `story.paragraphBreakAfterSentenceIds` 同步將中英故事分為兩個相連短段，旁白仍為一個全文 MP3。省略欄位的舊版維持原格式及 hash。
4. 查看 Prompt、模型與估價後，按按鈕產圖，或上傳現成圖片。審閱本場全部目標概念是否清楚可辨、圖片是否無文字。生成圖片完整置入 1600×900 的 16:9 畫布，避免裁掉目標物件；上傳圖片保留原尺寸，定位須以選用素材為準。
5. 在圖片上為各詞設定標籤位置與指向位置。座標使用 0–1 比例，亦可用數字欄位輸入，動詞指向動作、形容詞指向能表達該概念的姿態或區域。
6. 定稿後產生 Serena 英文故事旁白並試聽。字庫補音另外列出缺少的單字、英文解釋與例句，只補必要音檔，沿用有效的既有錄音。
7. 確認故事、圖片、位置與音檔審閱項目，建立不可覆寫的教材版本。先開前台預覽檢查圖上查詞、故事及錄音，再手動發布。

編輯可儲存草稿，不會自動生成或發布。內容變更會取消受影響的審閱標記；更新故事後，舊旁白因文字 hash 不符不能作為新故事錄音。固定成教材版本後，製作草稿立即唯讀；用「複製成新草稿」帶入故事、圖片、座標與旁白，重設 Prompt 預設及審閱狀態，再開始下一版。

前台指定版本預覽網址：`#/scenarios/<scenarioKey>/revisions/<revision>`。草稿與草稿媒體限管理者，未發布版本不出現在一般情境清單；權限由 API 驗證。

## 生成與工作狀態

故事沿用後台既有文字模型設定；圖片使用專案配置的 OpenAI／Google 圖片 API。瀏覽器後台產圖與先前透過 Codex 產生效果參考圖是兩個不同入口，API 金鑰保留在伺服器。

旁白使用固定的本機 Qwen3-TTS／Serena 設定，與文章的 Google／OpenAI 聲線設定分開。`SCENARIO_QWEN_TTS_URL` 由伺服器環境設定，不接受瀏覽器輸入端點，也不會啟動 TTS 服務或下載模型。

生成工作保存在資料庫：`queued`、`processing`、`done`、`failed`、`uncertain`、`cancelled`。外部請求送出前保存 attempt；工作定期續租，重啟後不會自動重送結果不明的請求。取消只能停止後續套用，已送出的供應商請求仍可能完成或計費；重試不明結果須明確確認。

生成依當時儲存內容快照執行。執行期間修改草稿不會被舊結果覆蓋；圖片及音檔保留為候選素材。錄音仍須與故事文字 hash 相符。失敗的字庫補音保留成功項目，重跑前重新核對缺件。

## 儲存與啟動

新增 migration：`1791504000001_scenario-studio.sql`，依賴既有 `1791504000000_scenarios.sql`。製作草稿、工作、attempt、素材、worker 心跳與版本保留資料分開儲存；正式教材仍使用既有不可覆寫的情境 revision。

Compose 的 API 與 `scenario-worker` 共用可寫的 `scenario-studio` volume（`SCENARIO_STUDIO_DIR=/data/scenario-studio`）。API 對正式 images volume 保持唯讀；獨立 worker 在「建立教材版本」時將核對後的素材複製到正式圖片／音訊 volume 並匯入 draft，發布仍由管理者另外執行。

`scenario-worker` 使用獨立 `scenarios` profile，一般啟動不會自動啟用。完成正式寫入／部署授權後才執行：

```bash
docker compose --profile scenarios up -d --build scenario-worker
```

啟動 worker 可能處理既有生成待辦並產生費用。既有 `./scripts/deploy.sh` 預設只加 `images` profile，不會順便加入 `scenarios`；若明示指定 `scenario-worker`，Compose 可啟動該服務。

本機 Node 可用 `npm run start:scenarios -w @el/worker`；必須明示正確資料庫、媒體目錄與模型設定。API 必須設定 `SCENARIO_STUDIO_DIR` 才啟用後台路由。Docker 的 TTS 端點預設 `http://host.docker.internal:8000/v1/audio/speech`；本機 Node 須明設 `SCENARIO_QWEN_TTS_URL=http://127.0.0.1:8000/v1/audio/speech`，未設時停用語音生成。

## 驗證與限制

一般測試使用 `_test` 資料庫與假生成 client，不呼叫真實 LLM、圖片或 TTS。使用既有 `npm test`、`npm run typecheck` 與前端 build 驗證；完整本機人工驗收記錄另列於交付回報。

結構驗證不代替人工審閱。全部目標概念是否在圖片中清楚出現、故事詞形是否正確、繁中翻譯與錄音品質，都要由管理者確認。第一版不包含批次四十場景自動發布、作答紀錄或多人管理。
