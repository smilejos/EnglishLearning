## 2. 每個情境的最低內容條件

| 項目 | 必須通過的準則 | 驗證方式 |
| --- | --- | --- |
| 身分與版本 | 固定 `scenarioKey`、繁中標題、正整數 revision；同 key／revision 不得換內容 | 契約及現存版本查核 |
| 目標詞 | 1–25 個不同單字、不同 GUID，`targetCount` 與實際陣列長度一致；限定選定的 basic／advance 聯集，依圖片線索選擇 n／adj／v | 套件／後台檢查＋實際 DB 比對 |
| 教學詞義 | 每詞保存 word、entryGuid、list、teachingPos、senseZh；詞性與本次意思符合字庫，圖與故事一致 | 機械關聯檢查＋人工詞義審閱 |
| 圖片 | 正式底圖無單字、翻譯、箭頭或答案文字；所有目標物件／動作／狀態有可辨認的線索，不被主要角色遮住 | 人工看圖；預檢只核對檔案與人工標記，沒有 OCR |
| 互動定位 | 每詞各有 label／object 的 0–1 比例座標；名詞指物件、動詞指動作、形容詞指可解釋的狀態 | 座標格式檢查＋桌機／手機目視與點擊 |
| 英文故事 | 涵蓋全部目標詞；每個英文 token 都有正確 GUID、字形範圍與目標詞標記；支援詞也在選定級別 | 全 token 映射檢查＋人工文法／語意審閱 |
| 繁中翻譯 | 逐句對應、自然易懂、不新增圖片中不存在的關鍵動作；全文與逐句合併一致 | 全文一致性檢查＋人工對讀 |
| 故事旁白 | 英文、Serena、清楚溫暖；MP3 實際可解碼與播放，全文和定稿故事相符；textSha256 綁定故事 | hash／格式／完整解碼＋完整試聽 |
| 目標字庫音檔 | 本場目標詞的單字、既有英文解釋與既有英文例句錄音可用；同 GUID／種類／文字 hash，實際檔案存在，缺漏補齊 | 目標音檔計畫＋正式 metadata／檔案核對＋播放抽查 |
| 素材可重現 | 本機檔案、SHA-256、格式、尺寸／時長及生成紀錄齊備；路徑安全，正式檔案位於指定 volume | 套件預檢、匯入器與媒體核對 |

以上是本批教材要求，不把所有條件宣稱為現有匯入器自動保證。離線匯入器不檢查單字音檔是否齊備，也不替代試聽；後台建立版本會檢查本場全部目標詞缺音。兩條路都遵守本文件，離線路徑另留人工／資料核對證據。

離線套件目前也要求保留 `assets.referenceImage` 參考圖；正式 volume 只採無文字底圖及旁白，不把參考圖複製成教材。底層 API 對故事支援詞的級別檢查不如套件／後台完整，因此不能跳過來源及正式字庫核對直接送 API。

### 選詞、圖片與故事的人工判斷

- 15 名詞＋5 形容詞＋最多 5 動詞是選詞目標，不為湊配額加入與底圖無關的詞。動詞線索不足可以少選；每詞都須貼合圖中物件、動作或可解釋狀態。跨情境重複單字可接受，不為去重犧牲自然情境。
- `full`、`plant`、`can` 等多義詞依本次詞性與意思教學；不把「分級符合」當成所有詞義都同樣簡單。原形與屈折形明確連結，例如 reads → read、books → book；指標合法仍須人工確認文法關係。
- 形容詞與部分動詞可由故事補足語境，但底圖仍須有合理可辨識線索。若線索牽強或易誤解，換詞或少選；不靠額外文字把答案畫進底圖。
- 沿用已確認的可愛、明亮、溫暖 3D 卡通方向與十區塊 Prompt。英文標籤由網站疊加，annotation／text 規則固定無燒字。推薦寬幅約 16:9；後台生成會整理為 1600×900，既有上傳素材保留實際尺寸，1672×941 客廳不用重做或硬裁切。
- 故事參考客廳八句、75 詞的密度，採短句、自然敘事；句數與時長是編寫參考，不另設尚未確認的硬性限制。不為塞入目標詞寫成物件清單。可用 optional `story.paragraphBreakAfterSentenceIds` 將中英故事呈現為兩個相連短段；分段不改全文文字，仍只使用一個完整英文 MP3。舊版省略此欄位維持原格式及 hash。
- 目前離線套件與正式契約的英文 tokenizer 對 apostrophe 用法有差異；第一批先避免縮寫及所有格。若要使用，先確認套件 check 與 import dry-run 都通過，不能只依一條檢查判定。
- 畫面可有非目標裝飾物，但不把 expert／未分類詞加入本批標籤或英文故事；台灣 7000、CEFR 不用來補放超出 basic／advance 範圍的詞。
- 優先重用有效錄音，不重做整個 advance 字庫。故事支援詞缺音可如實顯示「待準備」，目前補音範圍僅本場目標詞，不擴大為全故事字庫補音。

## 3. 一場一場完成的流程

每場完成前不批次啟動下一批生成／正式寫入。新修訂依現行契約，歷史十五詞序列沿用原流程，遇到缺件留下清單，再做下一個不受影響的備料工作。

1. **備料**：依底圖選定本場 1–25 詞，核對 GUID／級別／詞義；備妥故事、翻譯、無文字底圖、座標、旁白及字庫錄音。
2. **內容審閱**：完整看圖、讀故事與翻譯、聽旁白；留下審閱人、日期、版本及未解問題。既有「generated-awaiting-listening-review」等歷史標記不能代替本次紀錄。
3. **離線與目標查核**：通過嚴格套件預檢及 dry-run；先在 `_test` 核對正式前台互動，另唯讀核對實際目的資料庫名稱／伺服器、字庫、已有 revision、必要 migrations、媒體根目錄與有效備份。若 migration 尚未套用，記錄待辦，不讓匯入器代做。
4. **匯入 draft**：依已授權的逐一匯入範圍，複製這一場的底圖／旁白至確認的 volume、寫入不可覆寫版本；補音檔檔案與 metadata 是另列的實際寫入項目。未完成品保留在製作草稿／本機備料，離線匯入器目前拒絕不完整套件。
5. **指定版本驗收**：從後台開 `#/scenarios/<key>/revisions/<revision>`，核對這次版本，不用目前發布版代替；完成下節前台驗收。
6. **獨立發布**：匯入成功不自動發布。只有品質與正式環境驗收通過、且發布在已授權範圍時才發布指定 revision；再用一般前台入口確認可見。部署、migration、啟動生成 worker 也不由匯入命令暗中執行。
7. **留存結果**：記錄 key／revision、內容及媒體 hash、檢查結果、DB 目標、匯入時間、發布狀態與問題；再接續下一場。

使用者已授權的同一操作不重複索取許可。執行前把實際目標與異動列清楚；若新增部署、啟動生成服務或超出授權範圍的寫入，再就新增部分確認。一般驗證不呼叫付費模型／TTS，新增素材生成另遵守專案的明確授權與費用說明規則。

### 匯入版本的重跑與修正

- 同 key／revision、相同內容和媒體可以重跑；不同內容改成下一個 revision，不覆寫既有教材。
- 匯入或 COMMIT 結果不明時先查相同 revision 及 hash；不立即升版、重產或刪除媒體。既有匯入器會在同鎖下確認提交結果，無法確認時保留檔案。
- 改故事：重新核對詞形／翻譯／覆蓋、重綁旁白 hash，必要時重產與試聽。改圖：重新定位並驗收全部目標詞。修改固定版本：複製製作草稿或建立新套件版本，重做受影響審閱。
- 只匯入本場新情境或新 revision，不使用 `npm run seed`、重置資料庫或 `POST /articles`。

## 4. 匯入後的前台驗收

桌機及手機各走一次；記錄實際螢幕尺寸與結果。

- 圖片載入完整，本場全部標籤可讀、指向合理；手機放大與捲動可找到每詞，關閉後返回原畫面。沒有圖下重複單字清單。
- 圖片標籤點擊開 Modal；單字原形、分級、詞性、情境意思及完整字庫內容正確。本場目標詞逐一檢查入口及單字音檔，英文解釋、英文例句／繁中翻譯與錄音可用。
- 故事按鈕在「放大圖片」旁；點擊才開故事 Modal。英文可點字、支援屈折形連回原詞，繁中翻譯可展開；不常駐佔據圖下空間。
- 旁白完整播放；播放單字／解釋／例句會暫停故事，故事保留位置可繼續。開卡不自動播放，點字不自動收藏。
- 看圖學習顯示全部目標詞。看圖回想依本場實際存在的名詞／形容詞／動詞獨立揭曉、累加顯示，再次點選收起該類；可全部揭曉或全部收起。只開放已揭曉詞的查詞入口，全部目標詞揭曉前隱藏故事、翻譯及旁白入口；收起任一已揭曉類別時關閉故事並暫停旁白。底圖本身沒有答案。
- 未發布版本及其媒體限管理者；正式發布後一般讀者可從列表進入，版本與媒體沒有錯配。正式管理者權限保留，不以單一使用者系統為由取消檢查。

在 `docs/scenarios/packages/<套件資料夾>/import-review.md` 留存以下資料，敏感連線字串、密碼與憑證不寫入紀錄。

```text
情境編號／標題：

套件檔或製作草稿 ID：
目標詞數：__（1–25）；basic __／advance __；n __／v __／adj __
選詞／本次詞義／正式 GUID 核對：通過／待修正（證據）
圖片人工審閱／圖片 hash：
故事與翻譯審閱／故事文字 hash：
全部目標詞座標桌機／手機驗收：
Serena 旁白完整試聽／解碼／音檔 hash：
本場目標詞有效錄音／缺漏數／補音 manifest：
套件 check／dry-run 結果：
正式 DB 名稱／URL 主機:port／實際伺服器 IP:port：
既有 revision／必要 migration／備份識別：
```

狀態依序記為「待補齊 → 待匯入 → 已匯入待驗收 → 可發布 → 已發布」；任何阻擋問題標記「需修正」。`publishReady` 是套件工具的完整性旗標，**不是這份紀錄的「可發布」品質結論**。

## 6. 既有指令及其界線

客廳例子，從專案根目錄執行；其他情境替換套件路徑。

```bash
npm run scenario:package:check -- docs/scenarios/packages/living-room-15-v1/scenario.json --require-publish-ready
npm run scenario:import -- --package docs/scenarios/packages/living-room-15-v1/scenario.json --dry-run
```

兩者不連 DB、不生成、不複製、不發布。`publishReady` 不檢查正式字庫音檔、不判斷圖文語意或旁白讀對全文。

指定 `DATABASE_URL` 後，可用 `scenario:import` 的 `--package <套件路徑> --check-database` 唯讀檢查實際目標與字庫。不要把連線 URL 貼進文件；此腳本不讀 `.env`。實際匯入使用 `--apply`、`--confirm-database`、`--confirm-server`、`--image-dir`、`--audio-dir`；確認值以唯讀查核輸出為準，不猜測 DB／volume。

離線匯入的 MP3 檢查只核對檔案頭、hash 與故事 metadata，不保證完整解碼；需額外用 ffmpeg 完整解碼及試聽。後台上傳／生成音檔有 ffprobe 與完整解碼檢查，也仍需人工聆聽。字庫音檔 metadata 匯入不負責複製檔案，檔案落點需另確認。

格式與操作細節見 [產生與匯入流程](generation-import-workflow.md)、[情境製作後台](admin-studio.md)、[客廳套件](packages/living-room-15-v1/README.md)。
