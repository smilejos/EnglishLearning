## 已確認需求

1. **單一使用者系統**：以個人學習為前提，不擴充班級、多人共享或跨使用者混淆等情境。保留既有驗證與角色機制。
2. **主動收藏才加入複習**：每次開啟單字卡都提供「收藏單字」按鈕。使用者決定哪些單字需要複習；單純點擊或開啟單字卡不自動加入。
3. **可回到來源課文**：收藏保留原課文來源，複習時可返回該課文。直接定位原段落與標示單字是建議的操作細節。
4. **可組合篩選**：同時提供課業內／課外、單元、單篇課文、年級、類別與日期篩選。「課別」不限定為其中一種。
5. **自行切換兩種模式**：快速複習可直接查看內容；快速挑戰先回想再揭曉答案。兩者使用相同的待複習收藏。
6. **第一版挑戰採自行判斷**：看單字 → 回想 → 揭曉答案 → 選「記得／忘記」。先不做選擇題、拼字題或自動評分。
7. **熟悉後移除**：挑戰選「記得」視為成功，或手動點選「已熟悉」，皆將單字移出待複習清單；選「忘記」則保留。

## 已被取代的早期提案

- 最初曾討論自動保存每次點字，以點擊日期篩選；使用者後續改為主動收藏。**不要依早期提案實作自動加入複習或完整點擊事件追蹤。**
- 不以現有全站單字解釋的建立時間推斷收藏日期，也不把已有解釋的單字一律列為待複習。

## 已核對的程式基礎與實作入口

- `web-learner/src/App.tsx`：`WordPopup` 提供主動收藏，文字／圖片點字只開啟解釋；頂部可進入複習頁。
- `web-learner/src/VocabularyReview.tsx`、`lib/vocabulary.ts`：複習／挑戰、組合篩選、台北日與篩選保存。
- `web-learner/src/lib/route.ts`／App：`#/review` 及文章 hash 的 `paragraph`、`word`、`from=review` 參數，支援返回複習。
- `web-learner/src/types.ts`：文章已有 `materialType`、`grade`、`unit`、`category`、tags 等欄位。
- `api/src/routes/lookups.ts`：既有解釋查詢可重用；`POST /lookups` 為 reviewer/admin 產生解釋的功能，可能觸發 LLM/TTS，不適合作為收藏端點。reader 也應能使用收藏與複習。
- `api/src/routes/vocabulary.ts`、`shared/src/repo/vocabulary.ts` 與收藏 migration：獨立收藏 CRUD、熟悉狀態、來源快照與交易。`wordExplanations.ts` 仍保存共享解釋，不能代替收藏來源紀錄。
- `api/src/auth.ts`：已有登入身分；沿用既有機制即可，無需另建多人產品功能。
- 收藏 POST 驗證文章與段落歸屬；`/vocabulary` 頂層路徑同步於 nginx／Vite 轉發。持續以 `api/src/routeConfig.test.ts` 檢查。

## 主要驗收方向

- 點開單字卡不增加待複習項目，按收藏才增加；重複操作不產生意外重複項目。
- 篩選條件能組合，依收藏來源課文分類，日期使用最終確認的語意。
- 快速複習與快速挑戰可切換；揭曉答案本身不算成功。
- 「記得」與「已熟悉」移出清單，「忘記」保留；不刪除原課文或共用解釋。
- 從收藏可回原課文，來源不存在時有明確提示。
- 測試使用 mock，不呼叫真實 LLM／TTS／圖片 API；資料庫測試遵守 `AGENTS.md` 的隔離要求。
