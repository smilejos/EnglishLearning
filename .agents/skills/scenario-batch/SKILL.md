# 情境分類製作

把生活／學習主題做成一組能看圖、聽故事、點字查卡、按詞性回想的教材。對話與紀錄用繁體中文，故事與旁白用英文。保留既有修改、素材、版本與發布指標，接續實際進度。

## 開始時定位

所有 `docs/`、`scripts/`、`shared/` 路徑均相對 Repo 根目錄；用 `git rev-parse --show-toplevel` 定位，不依賴電腦絕對路徑。

1. 讀根目錄 `AGENTS.md`、`docs/codebase-architecture.md` 第 1–3 節及第 13 節任務路由。
2. 讀 `docs/scenarios/scenario-learning-requirements.md`、`docs/scenarios/import-criteria.md`、`docs/scenarios/generation-import-workflow.md`；使用後台加讀 `docs/scenarios/admin-studio.md`。功能與契約以當下程式、migration 為準。
3. 查工作樹、既有分類提案、套件與進度。判定新分類、修訂或接續中斷批次；不自動恢復其他暫停序列。
4. 取得分類名稱、場數、主題／對象、可重用素材及授權範圍。已有答案不再問；未指定場數先採 5 場並記錄假設，未指定分類主題則請使用者提供主題，期間做唯讀盤點。

接續／報錯至少用 scenarioKey＋revision 或套件路徑定位；「23 詞」「第三篇」不一定唯一，查現有清單仍無法定位時只問缺少的識別資訊。修訂前確認要求是否已完成，已合適且未變的版本直接重用，不為產生工作紀錄而空升版。

「分類」先落成批次規劃與教材清單。現行情境契約沒有分類欄位，不自行增加 DB 欄位、頁面或 migration，也不把 batch 欄位塞入 strict scenario content。

## 預設與範圍

- 未提供單字時，預設從 `level.list` basic＋advance 選詞，目標詞與故事支援詞遵守該批級別。
- **使用者提供單字時，切換為指定詞模式，不限制 basic／advance**；可採 expert 或未分級詞。先查字庫、重用匹配的詞條；缺詞則整理新增字庫資料並依授權入庫，讓圖片、故事與詞卡共用正式 GUID。讀 [使用者指定詞與缺詞入庫](references/user-vocabulary.md)。不得為通過舊驗證把詞偽標為 basic／advance。
- 指定詞模式的故事支援詞優先採簡單既有詞，但不再受 basic／advance 硬性限制；仍須逐 token 對應真實字庫詞條，必要缺詞一併列入新增計畫。
- 每場預設盡量 15 名詞、5 形容詞、最多 5 動詞；貼合情境優先，動詞不足可少選，其他類不得硬湊。使用者指定詞量／詞類優先，不為配額擅自刪除或補入其清單。現行契約接受 1–25 詞，`targetCount` 等於實際數量；超量先合理拆場， unsupported 詞類／片語先查契約支援。
- 全部目標詞自然融入故事，必要時兩個相連短段；一份全文英文 MP3，逐句繁中翻譯，不增加中文旁白。
- 底圖採明亮、溫暖、可愛 3D 卡通與寬幅構圖；沒有英文標籤、翻譯、箭頭或答案，互動文字由網站疊加。
- 新圖片沿用使用者指定工具；本工作脈絡偏好 Codex CLI，語音偏好 local Qwen3-TTS／Serena。查實際可用工具、設定與適用的 `imagegen` 技能，不杜撰 CLI 指令，不默默改用遠端 TTS。
- 調用技能不自動授權正式庫寫入、發布、部署、migration 或啟動生成服務。逐場匯入已有明確授權就持續執行，不重問；指定教材發布授權不包含服務更新。
- 新素材生成沿用本次對話的工具／費用授權；未明確授權真實生成時，先完成可審閱的選詞、故事與缺件計畫，再說明生成需求並確認新增部分。一般驗證不呼叫圖片、LLM 或 TTS，不以測試為由重產素材。

## 分類規劃

在 `docs/scenarios/preparation/<batch-key>/` 建立 `batch.json` 與 `review.md`。新 key 採小寫英數與連字號，查既有 key 避免撞名；批次檔是工作紀錄，**不是**匯入套件。

`batch.json` 至少保存分類 key／繁中名稱、選詞模式（預設分級／使用者指定）、預設模式的級別或指定詞原始清單、場數、授權範圍，以及每場順序／key／標題／核心活動／素材來源／預定 revision／n-adj-v 實際數量／進度／證據路徑。指定詞模式另記詞條重用／待新增／已入庫及契約相容狀態。不得保存機密。備料時記候選與問題，完成後才填真實 hash、時間與結果。

一場有一個清楚活動與可辨識物件群；各場在地點、活動或學習重點上有差異，排序由熟悉、具體到稍複雜。可重複自然出現的核心詞，不為跨場去重犧牲情境。

使用者只要求規劃時，交付批次清單、逐場候選詞／已存在 GUID／詞義／圖中線索、故事與翻譯草案、待新增詞條、可重用素材與缺件清單即可。缺詞標記待入庫，不把計畫 GUID 當成已存在；不生成、不匯入，也不宣稱完整套件可發布。

## 逐場完成

1. **選詞與圖片判斷**：讀 [內容與素材](references/content-and-media.md)。先看實際底圖；新場先聯合規劃物件／狀態／動作與候選詞，生成後再看圖修正。每詞留下圖中線索與採用／淘汰原因。
2. **定稿與缺詞準備**：依選詞模式核對 GUID／級別或指定來源／詞性／詞義，寫故事、翻譯、token 映射及座標。預設模式可換不適合的候選詞；指定詞模式先調整場景、拆場或底圖支撐清單，不擅自換掉使用者指定詞。缺詞先做可審閱字庫增量，正式入庫與契約相容通過前不當作完整套件。
3. **生成缺件**：圖／文確認後，只生成缺少或失效的全文旁白及本場目標詞音檔。保存來源、hash、文字 hash、生成設定及審閱狀態。
4. **套件與匯入**：讀 [匯入與驗收](references/import-and-acceptance.md) 與 [Repo 工具路由](references/repo-tools.md)。先離線 check／dry-run，於受保護 `_test` 環境核對前台互動，再唯讀核對實際 DB、migrations、字庫、volume、備份與運行中 API 契約。按授權匯入不可覆寫 draft。
5. **指定版本驗收**：核對圖、詞卡、故事、音源仲裁，以及桌機／手機的學習與分類回想；記錄已做、未做及阻擋。不以 `publishReady` 代替品質驗收。
6. **接續下一場**：本場通過相應 gate 才接下一場生成／正式寫入。受阻時保留原因，可做其他場離線備料，不跳過 gate。素材、manifest 與正式寫入逐場處理，不並行寫共用資源。

修訂已匯入教材採下一個 revision，原版本與 hash 不變。只有座標／選詞變更且圖片仍合適可重用底圖；全文英文未變可重用有效旁白，但新版本媒體 metadata／路徑仍須合法。中斷先查檔案、DB 版本與 hash，再決定重跑，不直接刪檔或升版。

## 交付

- 每場 `docs/scenarios/packages/<scenario-key>-r<revision>/scenario.json`、相應素材或安全 Repo 內來源路徑、`import-review.md`。
- 批次清單／總審閱：分類名稱、詞性數量、替換原因、版本／hash、缺音與生成數、預覽連結、check／dry-run／postcheck／UI 結果、實際狀態及待辦。
- 分別列「教材完成」「正式 draft 匯入」「品質可發布」「已發布」「程式已部署」，不以其中一項推定其他項完成。
- 依 `AGENTS.md` 的驗收與 Git 流程收尾，不把技能調用當作 commit／push／部署授權。
